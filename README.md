# 片山英単語 · NuASA

2,000語を学ぶ、端末内保存の英単語PWAです。iPhone・Android・PCから同じURLで利用でき、初回の読み込み後はオフラインでも学習できます。App Store / Google Playへの登録は不要です。

**バックエンド・APIサーバー・クラウドDB・認証サーバーはありません。GitHub Pagesの静的ファイルだけで動作します。学習データは各端末内に保存されており、GitHubや開発者のサーバーには送信されません。** アクセス解析・広告・外部フォント・トラッカーも使用しません。

## 利用者向け

公開されたURLをブラウザで開いてください。PythonやNode.jsのインストールは不要です。

| 端末 | アプリとして追加する方法 |
|---|---|
| iPhone | **Safari**でURLを開く → 共有 → **「ホーム画面に追加」**。表示された場合は「Webアプリとして開く」をオンにする |
| Android | **Chrome**でURLを開く → メニュー → **「ホーム画面に追加」または「アプリをインストール」** |
| PC | **Chrome / Edge**等でURLを開く → アドレスバーやメニューのインストール操作でPWAとして追加 |

インストールせずブラウザのままでも利用できます。最初はオンラインで開き、設定画面に「オフライン準備完了」と出てからオフラインで利用してください。HTTPSが必要です（開発時のlocalhostは例外）。

### 学習の使い方

- 基礎・応用・上級Ⅰ・上級Ⅱの各500語、合計2,000語。チェックボックスで範囲を自由に選択します。
- 英語→日本語の6択。同じ品詞でそろえ、同じ訳・紛らわしい登録類義語の混在を避けます。同一起動中は前回と違う選択肢の組み合わせになります。
- 通常コースはランダム・苦手優先・未学習のみ・復習日が来た単語の4モード。問題数1〜対象語数（最大2,000）、1問3〜120秒。
- **1日の目標は初期50語**。「目標を変更」で1〜2,000語に変更します。
- **目標のコース**は毎回目標数ちょうど。**半分のコース**は目標÷2を切り上げた問題数（例：51語なら26問）。残りの不足語数だけを出す方式ではありません。
- 目標・半分コースは選択範囲と秒数を使い、通常のモード・問題数から独立します。今日未回答の語を優先し、足りない分は今日回答済みから補います。1コース内では重複しません。
- 回答後に正解を確認し、自分で「次の単語へ」を押します。PCでは数字1〜6、回答後にEnterでも操作できます。
- 問題画面は2列×3段の選択肢と画面下部の「次の単語へ」を同じ画面内に配置します。回答後は全選択肢の日本語の下に対応する英単語を表示します。横向きでは問題と選択肢を左右に配置します。大きな文字への拡大時は内容を切り捨てず、必要に応じてスクロールできます。
- リザルトの「今回の単語」はページ切り替えなしで全件を表示します。スクロール案内、通し番号、末尾の完了表示で一覧の範囲を確認できます。
- アプリを切り替えている間も時間は進みます。期限ちょうどの回答も時間切れです。回答確認中は止まります。
- 今回の間違いだけの復習、学習カレンダー、コース別進捗、最近10回のコース履歴を利用できます。
- 回答ごとに保存します。途中終了・ブラウザ終了後も回答済みの記録が残ります。中断位置からのコース再開はありません。

### 記録の数え方

| 項目 | 定義 |
|---|---|
| 今日／日別の学習語数 | 同じ日の同じ単語は何度回答しても1語。誤答・時間切れも数える |
| 月の学習語数 | 日別学習語数の合計。別の日に復習した単語は再び加算 |
| 月内の重複を除く語数 | 同じ月の同じ単語を1語として数える |
| 回答回数・正答率 | 再回答を含むすべての回答。正解数÷回答数 |
| 連続学習日数 | 1回答以上した日の連続数。今日未回答なら昨日までの連続数 |
| 苦手優先 | 誤答経験があり連続正解3未満の語を優先。その中では連続正解数・正答率の低い順 |
| 復習日 | 正解後は連続正解に応じ1・3・7・14・30・60日後。不正解・時間切れは10分後 |

日付は端末のローカル時刻です。目標達成は100%まで表示し、学習語数はそれ以上も加算します。時差・端末の時計変更は集計や復習日に影響します。

### プロフィール・バックアップ

右上の名前、または「設定」から操作します。同じ端末で複数人が利用するときはプロフィールを切り替えてください。新規プロフィールは初期設定から始まり、記録は独立します。名前変更・削除も可能です。

「学習データを書き出す」で、**全プロフィール**を `vocabulary-backup.json` に保存します。名前・設定・セッション・全回答・単語別成績・復習予定を含み、カレンダーや統計を再現できます。

「学習データを読み込む」でJSONを選び、表示されるプロフィール数・回答数を確認して復元します。**既存の記録を上書きせず、新しいプロフィールとして追加します。** 同名でも別の項目になります。何度も同じファイルを読み込むと、その回数分のコピーが追加されます。不要なコピーは削除してください。

形式・バージョン・参照先・値の範囲・重複回答・成績と履歴の整合性を検証し、全データの検証後に一括保存します。無効なJSONや未対応バージョンでは保存しません。読み込みの上限は50MB、100プロフィール、全体25万回答（各プロフィール20万回答）です。

端末間の自動同期はありません。URLを共有しても学習記録は共有されません。**端末・ブラウザ・公開URLごとに保存領域は別**です。サイトデータ削除、プライベートブラウズの終了、端末故障などで記録が消える場合があるので、定期的にバックアップしてください。Safariの通常タブとホーム画面アプリ間で記録が共有されるかに依存せず、必要な場合は書き出し・読み込みを使ってください。

## 開発者向け

### 必要環境とローカル起動

- Node.js **22以降**とnpm（推奨Node.js LTS）。本番の利用者には不要です。
- Python **3.12**：Python版比較テスト・既存データ変換を行う場合のみ必要。
- 通常のブラウザ。ランタイムの外部依存ライブラリはありません。

```sh
npm ci
npm run dev
```

`http://127.0.0.1:4173/` を開きます。開発用サーバーは静的ファイルを配るだけで、本番には含まれません。自動再ビルドはありません。変更後は `npm run build` して更新してください。PWAのキャッシュがある場合は「更新する」を選ぶか、開発者ツールでService Workerを解除します。

### ビルド

```sh
npm run build
npm run preview
```

配布物は **`dist/` の中身だけ**です。HTML・CSS・JavaScript・JSON単語データ・PNGアイコン・Manifest・Service Workerからなります。Python、テスト、学習記録、node_modulesは含まれません。HTMLをダブルクリックして `file://` で開く方法はPWA用ではありません。

TypeScriptのコンパイラーだけでブラウザのES Modulesに変換します。React・Vite・状態管理ライブラリ・UIライブラリは使用しません。パッケージは開発／テスト用途のみです。

### GitHub Pagesに公開する

HTMLに `noindex, nofollow, noimageindex` を指定し、対応する検索エンジンにページと画像の検索除外を依頼しています。これはアクセス制限ではありません。URLを入手した人は閲覧でき、直接参照された画像や指示に従わない検索エンジンの掲載を完全には防げません。公開リポジトリの場合はソースと画像も閲覧できます。URLは共有したい相手に直接伝えてください。

プロジェクト配下の `robots.txt` はドメイン全体の検索設定にならず、クローラーを遮断するとHTMLの `noindex` を読めなくなるため、代わりに上記のmeta指定を使用しています。

公開先は [片山英単語](https://ryoyakatayama.github.io/katayama-english/)、ソースは [ryoyakatayama/katayama-english](https://github.com/ryoyakatayama/katayama-english) です。mainへのpushでテスト後に自動更新します。以下は別のリポジトリへ設置するときの手順です。

1. GitHubでリポジトリを作成します（無料プランの場合は公開リポジトリを選ぶなど、Pagesを利用できる設定にしてください）。
2. このプロジェクトのソースをリポジトリのルートに置きます。`work/`・`outputs/`・`node_modules/`・個人の `data/` は不要です。`.gitignore` に含めています。既存リポジトリに入れる場合はその設定を使ってください。
3. GitHubの **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択します。
4. 新規の空リポジトリへ登録する例：

```sh
git init -b main
git add .
git commit -m "Add Katayama vocabulary PWA"
git remote add origin https://github.com/YOUR_NAME/YOUR_REPOSITORY.git
git push -u origin main
```

5. Actionsの **Test and deploy to GitHub Pages** が完了すると、Pagesに表示されるURL（通常 `https://YOUR_NAME.github.io/YOUR_REPOSITORY/`）を共有できます。

ワークフローはmainへのpushと手動実行に対応します。PRではテストだけ実行します。Node/Pythonの準備 → 依存の固定インストール → Python版テスト・比較用データ作成 → TypeScriptビルド・単体テスト → Chromium/WebKitブラウザテスト → `dist/` のみをPagesへアップロード・デプロイ、の順です。デプロイ権限は専用ジョブだけに付与します。ホスティング以外のサーバーは作成しません。

すべてのパスは相対パスです。リポジトリ名をビルド設定へ書き込む必要はありません。サブディレクトリ配下でManifestのstart_url/scope、Service Workerのscope、単語・アイコン・JavaScriptが同じ範囲に収まります。

### テスト

```sh
python -m unittest discover -s legacy-python -p test_app.py
python scripts/python-parity.py
npm test
python -m unittest discover -s tests -p test_conversion.py
npx playwright install chromium webkit
npm run test:browser
```

ブラウザテストは `/katayama-test/` 配下で実行します。PC、iPhone相当のWebKit、Android相当のChromiumを対象とし、オフライン、ブラウザ終了後の保持、プロフィール分離、JSON復元、スマートフォン表示を確認します。更新テストは共有配布ファイルを書き換えて戻すため、ワーカー数は1です。比較用カレンダーデータはAsia/Tokyoに固定しています。

Playwright WebKitはiPhone実機ではありません。完全終了後のオフラインテストでは、アプリと独立したページのCache API保存も診断します。WebKit自体がその値を再起動後に保持できない場合だけ、そのケースを制約としてスキップします。学習記録のオンライン再起動後の保持と、通常のオフライン再読み込みは別々に検証します。詳しくは `docs/TESTING.md` を参照してください。ホーム画面への追加・完全終了後のオフライン起動・OSのインストール画面・実機のソフトウェアキーボードは、公開後に実端末でも確認してください。

### Python版の記録を移す（任意）

Python版は `legacy-python/` に元のソースを保持しています。従来のWindows配布物も削除していません。PWAの通常利用にPythonは不要ですが、SQLite変換をするPCではPythonを使用します。

Pythonアプリを終了し、元の `data` フォルダーをバックアップしてから、次を実行してください。

```sh
python scripts/convert-python-backup.py "旧アプリのdataフォルダー" --name "自分の記録" --output vocabulary-backup.json
```

生成したJSONをPWAの設定画面から読み込みます。変換は元のSQLiteを**読み取り専用**で開き、原本を変更しません。既に存在する出力ファイルは上書きしません。個人別フォルダーごとに異なる出力名で変換できます。保存済みの目標値は引き継ぎ、新規PWAプロフィールだけを初期50語とします。

## 構成と保存方式

| ファイル | 役割 |
|---|---|
| `src/engine.ts` | 出題・正誤・復習・カレンダー集計。画面・保存から独立 |
| `src/model.ts` | 単語・プロフィール・設定・履歴の型 |
| `src/storage.ts` | IndexedDBのトランザクション、全プロフィールバックアップ |
| `src/backup.ts` | バックアップv1の厳密な検証・正規化 |
| `src/main.ts` | 画面・操作・タイマー・インストール／更新案内 |
| `public/` | HTML、CSS、Manifest、NuASAアイコン |
| `scripts/build.mjs` / `sw-template.js` | 単語データ変換、静的ビルド、キャッシュ版生成 |
| `.github/workflows/pages.yml` | 自動テストとPagesデプロイ |
| `legacy-python/` | 変更前のPython版ソース・語彙・テスト・ライセンス |
| `docs/MIGRATION.md` | 実装調査、維持する仕様、Python→PWA対応表 |
| `docs/TESTING.md` | 検証結果と未検証事項 |

IndexedDB名は `katayama-v1:<公開パス>`。DBスキーマversion 1、`profiles`ストアにプロフィール単位の履歴・設定・成績、`meta`ストアに最後に選んだプロフィールIDを保存します。回答追加と単語成績更新は同じトランザクションで行い、二重保存を除外します。別タブの書き込みも、最新のプロフィールをトランザクション内で読んでから更新するため失いません。全プロフィールのエクスポートも単一の読み取りトランザクションです。

時刻はUnixミリ秒、回答時間は秒です。日別・月別統計は履歴から計算します。プロフィール単位の保存を採用し、構成を単純にしています。長年の大量履歴では読み書きが重くなる可能性があります。将来はIndexedDBのスキーマ更新で履歴ストアを分離できます。

JSONは `format: "katayama-vocabulary"`, `version: 1` を持ちます。将来は `backup.ts` に旧形式→新形式の変換を追加できます。未対応版を推測で読み込むことはしません。

## PWAの更新方式

ビルド内容からSHA-256の版IDを生成し、JavaScriptを `assets/<版ID>/` に配置します。Service Workerはその版のHTML・CSS・JS・単語・アイコン・Manifestを一括キャッシュします。1つでも取得できなければ新しい版のインストールを失敗させ、旧版を維持します。

起動・オンライン復帰・ウィンドウ復帰時に更新を確認します。新しい版があれば「更新する」を表示し、操作時に待機中のWorkerへ `skipWaiting` を送ります。コース中には更新ボタンを表示せず、別タブが更新しても回答中の画面を再読み込みしません。コース終了後に更新できます。全タブを閉じた後は新しい版が通常どおり有効になります。

有効化時は同じ公開パスの古いキャッシュだけを削除し、学習記録のIndexedDBや他のPagesアプリのキャッシュは削除しません。Worker登録には `updateViaCache: "none"`、初回キャッシュ取得には `cache: "reload"` を使用します。オフラインでは現在の版を継続して使います。

仕様の参照： [GitHub Pagesのカスタムワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[MDN: Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)、[Apple: Webサイトをアプリにする](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)。
