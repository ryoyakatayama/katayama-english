# Python版の調査と移植設計

調査対象は `work/project-calendar` の全Pythonファイル（app / engine / progress / selftest / test_app / build_windows）、語彙・類義語データ、READMEです。変更前のソースは `legacy-python/` に保存しました。

| Python版で確認した実装 | PWAでの置き換え |
|---|---|
| Tkinter Canvasのホーム・問題・結果・学習記録画面 | フレームワークなしのTypeScript、HTML、レスポンシブCSS |
| vocabulary.txt / vocabulary_upper.txt の `[level,pos]` と `英語=日本語` | ビルド時に同じ2,000語をJSON化。4レベル各500語を維持 |
| synonyms.txtの英単語グループ | 同じグループをJSON化して選択肢除外に使用 |
| data/learning.sqlite3 の sessions / attempts / progress | IndexedDB。プロフィールIDに紐づけて履歴と成績をトランザクション保存 |
| data/settings.json の範囲・モード・問題数・秒数・日目標 | プロフィール別設定。初期値のみ目標20→50語に変更 |
| 個人ごとにアプリの保存フォルダーをコピー | 端末内のプロフィール作成・選択・改名・削除 |
| フォルダーコピーによるバックアップ | バージョン付きJSONの全プロフィール書き出し・検証後の追加読み込み |
| PyInstallerによるWindows配布 | Manifest・Service Worker・静的ファイルのGitHub Pages配布 |

## 維持する学習仕様

- 選択したレベルだけから出題。通常は重複のない無作為抽出、レベル別均等割りではありません。
- 6択は同品詞。同じ日本語、片方の訳を含む訳、登録された類義語を相互に除外。同レベルを優先し、選択中の他レベルを補充に使用。直前と同じ選択肢集合を避けるため最大100回試行します。選択肢の記憶は起動中のみです。
- 苦手優先は「過去に誤答あり、連続正解3未満」を最優先。その中では連続正解数、正答率の昇順。次が未学習、最後がその他。同順位を無作為化して抽出後に出題順を再シャッフルします。
- 未学習は成績のない語、復習日は学習済みかつ due_at <= 現在時刻の語。未学習語は復習日モードに入りません。
- 正解後の復習間隔は連続正解に応じ1・3・7・14・30・60日（以後60日）。誤答・時間切れは連続正解0、10分後。
- 制限時間3〜120秒。締切ちょうどの回答も時間切れ。二重回答は集計しません。回答後は次へを押すまで待ちます。数字1〜6、Enter操作を維持します。
- 回答ごとに即時保存。途中終了でも回答済みの履歴を維持。途中の出題位置の再開は元からありません。強制終了したセッションも記録画面では「途中まで」と表示します。
- 結果に正答率・回答時間・単語一覧・今回の間違いの復習。割合の整数丸めはPythonの偶数丸めを維持します。
- 日別語数は端末ローカル日付内の異なる単語数。誤答・時間切れも1語。月の合計は日別語数の合計、月内ユニーク数・回答数は別表示。連続日数は1回答以上の日の連続（今日未回答なら昨日まで）。
- カレンダー月移動・日別詳細・4コースの学習済み語数／3連続正解数・最近10セッションを維持。
- 目標コースは通常のモード／問題数とは独立し、チェックした範囲と秒数を使用。今日未回答の単語を優先し、足りなければ今日回答済みから補充。毎回目標数ちょうどを出題（残り語数ではない）。追加の半分コースは目標÷2の切り上げ。

## 意図的な変更

- 初期目標50語、半分コース、プロフィール・JSONバックアップ・PWA更新操作を追加。
- SQLiteの秒単位時刻はPWA内でミリ秒へ統一。日付集計は端末のローカル暦日で行います。
- PythonとJavaScriptの乱数生成器は異なるため、同じ乱数シードで同じ並びにはなりません。抽出規則・分布・制約を維持し、確定的な判定と集計を比較テストします。
- 保存失敗時は黙って一時保存へ切り替えず、表示して回答の再保存を可能にします。
- 結果一覧はスマートフォンでスクロールして閲覧できます。
- PythonのSQLiteファイルはブラウザから直接読めません。付属のオフライン変換スクリプトでPWA用バックアップに変換できます。

## 保存・公開境界

静的配布物だけを `dist/` に生成します。Python、利用者のdata、テストデータ、開発ツールは配布物に入りません。バックアップは既存プロフィールを上書きせず新しいIDで追加し、形式を完全検証してから1トランザクションで保存します。学習情報を送る通信処理はありません。
